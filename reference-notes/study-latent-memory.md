# Latent-memory 学习笔记

## 项目定位
不是聊天App，是**跨窗口长期记忆工具**。解决"开新窗口就失忆"的问题。Python MCP server，本地优先，零第三方依赖。

## 核心架构：四层数据
1. **人格文件**（每轮常驻）：身份、相处原则、里程碑索引、检索约定。CLAUDE.md/persona.md
2. **记忆库**（按需检索）：已发生事件的完整叙述+当下状态。timeline/*.md + 索引摘要
3. **未解决清单**（换窗优先）：当前未结束事项。换窗时最先召回
4. **会话线索**（历史快照）：上次聊到哪、窗口结束状态。threads.jsonl

## 关键设计思想（可学习）

### "知道该查" vs "查得到"
- 人格文件负责"知道该查"——告诉模型何时应检索记忆
- MCP工具负责"查得到"——实际执行检索
- 两半缺一不可。光有工具模型不会主动调用

### 记忆不是评语
- 记录发生了什么、原话、当时状态
- 不写"你应该温柔"这类判断句
- "形容词长不出人格，只会长出一个会背评语的模型"

### 注入契约五条（自建前端必读）
1. 人格文件**逐字完整注入**，不摘要不改写
2. **每轮请求都在**，不是只在第一轮（最隐蔽的坑）
3. 每次会话**从磁盘重读**，不缓存
4. 放在system位置或等价前缀
5. 不进上下文压缩

### 其他设计原则
- **用进不废退**：被检索命中的记忆权重上升，不做时间衰减
- **病灶迁移**：每段记录必须以"现在的状态"收尾
- **撤回账本**：纠错不是静默覆盖，走撤回链
- **记忆只有TA能改**：用户只能写便条说哪里不对，改不改由AI判断

## 山屋（前端可视化）
- 巴塔哥尼亚山屋隐喻的记忆浏览界面
- 磁带=每天正文，事实簿=拆出的小事实，浮冰=随机事实
- 石堆=被想起最多的5段，拍立得=近7天换窗记录
- 火漆信=上个窗口留话，地图=未解决清单
- 唯一可写：小锁信（告诉TA哪里记错了）

## 检索实现
- 零依赖档融合三路：BM25 bigram + 语义路 + 关系图谱
- RRF融合排序
- 可选本地embedding（fastembed）或云端embedding

## 对我们的启发
1. 我们已有类似的3层上下文（system prompt + 记忆摘要 + 近期消息），但没有"未解决清单"和"会话线索"
2. "知道该查 vs 查得到"的分离已通过tools实现（read_file工具）
3. 注入契约提醒：system prompt必须每轮都在、不进压缩——我们的prompt caching已做到
4. 山屋的可视化隐喻很有意思，但对当前前端开发不直接相关
5. 撤回账本和变迁链是成熟记忆系统的做法，未来可考虑
