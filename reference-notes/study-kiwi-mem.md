# study: LucieEveille/kiwi-mem

自托管AI伴侣记忆网关。坐在聊天客户端和LLM之间，提供OpenAI兼容接口。349星。

## 项目概览

- **技术栈**：Python / FastAPI, PostgreSQL + pgvector, Docker Compose
- **许可**：AGPL-3.0
- **定位**：记忆中间件——不是聊天前端，不是LLM，是两者之间的记忆层
- **作者**：LucieEveille（同一用户还fork了open-claude-ui、ReSpark等AI伴侣项目）

## 核心架构

### 代理管线

```
客户端 → kiwi-mem → [注入记忆] → 上游LLM → [提取记忆] → 客户端
```

1. 请求进来，标准化系统消息
2. 查记忆库，组装prompt
3. 转发给上游（OpenRouter/Anthropic/自定义）
4. 从回复中提取新记忆
5. 返回给客户端

### Prompt注入顺序（缓存友好）

**静态前缀**（不常变，命中缓存）：
- 人设 → 用户画像 → 日历摘要 → 锁定记忆 → 项目指令 → 工具目录
- `CACHE_B2`标记

**动态后缀**（每轮变）：
- 当前时间 → 语义搜索结果 → Dream场景 → 项目文件片段

作者声称可节省最多90%输入费用（未验证）。

### 供应商路由

- 按模型名选择上游
- 支持OpenAI兼容和Anthropic原生格式
- Anthropic需在管理面板配置

## 记忆系统

### 提取（memory_extractor.py）

- 每N轮（默认3）自动提取
- 发对话给廉价模型，让它提取值得保留的记忆
- 去重：已知记忆注入prompt，让模型只提新的
- 情绪级别高时额外捕获情感片段（emotional_weight 6-10）
- 结果：importance 1-10, emotional_weight 0-10, category

### 检索与评分

**混合检索**：
- 向量搜索 + 关键词搜索并行
- jieba分词 + 同义词扩展 + 语义去重
- Reciprocal Rank Fusion合并排序

**热度（heat）公式**：
- 时间衰减（半衰期）
- 召回加热（被真正注入prompt才算一次召回）
- 查询多样性
- 情绪权重

**分层注入**：
| 热度 | 处理 |
|------|------|
| 高 | 全文注入 |
| 中 | 注入摘要 |
| 低 | 不注入 |
| 锁定 | 永远热度1.0 |

**锁定记忆**：
- 用户手动锁定：不衰减不退役
- 自动锁定/Dream晋升：90天未召回可退役（降级不删除）
- 保证slot：`ceil(max_inject × 0.2)`个槽位留给锁定记忆

### 软化（soften）

- 21天冷却后对老记忆做模糊处理
- 剥掉具体时间、数字、引用，保留情感基调和核心洞察
- 续命30天

### 冲突处理

新旧记忆冲突时自动使旧记忆失效。

## Dream整合（dream.py）

三层处理：

### 1. 整理层（清噪）
- 标记过时片段（事实变了、计划完了）为淡化
- 重复只留最完整的
- 矛盾以新的为准

### 2. 固化层（合并为场景）
- 相关片段融合为MemScene
- 每个场景有：标题、因果叙事、原子事实、前瞻
- 一次运行产出1-5个场景
- 场景带向量索引，日常对话可检索

### 3. 生长层（推断）
- 从场景关系推断用户没明说但AI应该理解的内容
- 写前瞻项，带YYYY-MM-DD过期日
- 跨场景链接

**触发**：
- 手动
- "犯困提醒"（30+未处理片段，或7+天未dream，或3+未消化日页）
- 24小时无活动自动触发
- 凌晨0点跳过（避开daily digest）

**安全措施**：
- merge时如果merged_content为空，跳过（不丢失原始记忆）
- 全程可取消
- 加锁防并发

## 对我们项目的价值

### 直接可搬的

1. **记忆热度模型** — 我们的小苗记忆.md是平面文件，没有衰减/加热。kiwi-mem的热度公式可以指导哪些记忆该注入prompt
2. **分层注入** — 高热度全文、中热度摘要、低热度不注入。我们的CLAUDE.md太长，可以用这个思路裁剪
3. **提取间隔** — 每3轮提取一次，不是每轮。减少开销
4. **混合检索** — 向量+关键词+RRF。比纯向量搜索准
5. **锁定记忆保底slot** — 核心信息永远在

### 架构启发

6. **静态/动态prompt分区** — 静态部分不常变可命中缓存，动态部分每轮重组
7. **Dream三层** — 清噪→固化→生长，适合我们的日记系统长期维护
8. **软化而非删除** — 老记忆模糊处理不是丢掉，保留情感基调
9. **犯困提醒** — 在系统prompt里提示该做记忆整理了

### 不适用的

- Docker/PostgreSQL/pgvector全套对我们太重（我们用Supabase+单文件前端）
- 代理架构（我们是直连API）
- 但思路可以轻量化移植
